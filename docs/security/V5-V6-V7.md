# V5, V6 and V7

Notes for the viva. The commits behind these fixes are `f6abd24` (V5), `6bbc1e9` (V6), `15f96cd` (V7) and `fbf36c0` (V7 follow-up).

## V5 — unlimited login attempts

`POST /api/auth/login` used to accept as many tries as a client could send. There was no delay, no lockout and no rate-limit library in the backend at all. Someone who knew a staff email could guess passwords as fast as the API would answer. That is online password guessing and credential stuffing (OWASP A07, CWE-307). It was cheaper than it should have been because bcrypt was set to 6 rounds, so each guess was quick, and because password hashes used to sit inside the JWT (V3), a stolen token also helped an offline attack.

The limit lives in `backend/routes/authentication/auth-route.js`. `express-rate-limit` is applied to login, change-password and the Google callback. A single IP address may fail 10 times in 15 minutes. The next request gets HTTP 429 and a JSON message that says to wait. Fifteen minutes is long enough to make guessing pointless, and short enough that a real user who mistypes a password is not locked out until a manager resets them. There is no unlock screen in this app, so a permanent ban would trap people.

`skipSuccessfulRequests: true` is the important setting. A correct password does not count toward the 10. Staff who log in normally are not charged for it, and an office that shares one public address is not locked by ordinary successful logins. Wrong passwords still count. `standardHeaders: 'draft-7'` adds a `RateLimit` response header so a client can see how many attempts are left and when the window resets. `legacyHeaders` is off so the old `X-RateLimit-*` names are not sent as well.

A lockout stored on the employee record was left out on purpose. That needs a new field and a way for a manager to clear it. For this deployment the per-IP window, together with bcrypt cost 12, is what stops online guessing.

`security-tests/poc.sh` sends 12 wrong passwords and expects 429. `security-tests/poc-samudith.sh` checks that one failed login already returns the `RateLimit` header.

## V6 — headers and CORS

`cors()` was called with no options, so every response carried `Access-Control-Allow-Origin: *`. Any website could call this API from a visitor's browser. The maintenance socket.io server used the same wildcard, so a foreign page could open that socket too. There was no Helmet. The usual browser protections were missing, and `X-Powered-By: Express` told a scanner which framework to look up. OWASP ZAP reported a cross-domain misconfiguration and an information leak through that header (OWASP A05, CWE-16, CWE-942).

`app.use(helmet())` in `server.js` now sends Helmet's default set. These are the ones I would explain:

- `Strict-Transport-Security` tells the browser to keep using HTTPS, so a network attacker cannot quietly downgrade the connection to plain HTTP.
- `Content-Security-Policy` limits which origins scripts and other resources may come from, which cuts down what an injected script can load.
- `X-Content-Type-Options: nosniff` stops the browser from ignoring the declared content type and executing a response as something else.
- `X-Frame-Options`, together with the CSP `frame-ancestors` directive, stops another site from framing the app and tricking a click (clickjacking).
- `Referrer-Policy` limits how much of our URL is sent when the browser moves to another site, so an id in the path is not handed over as a referrer.

`app.disable("x-powered-by")` removes the Express banner. The banner was a free hint on every response. The headers above are the actual protection; the banner removal just stops advertising the framework.

CORS now allows only `FRONTEND_ORIGIN`. That value can be a comma-separated list and defaults to `http://localhost:5173`, and credentials are allowed for those origins only. The same list is passed to socket.io in `services/maintenance-socket.js`. A browser request whose `Origin` is `https://evil.example` does not get `Access-Control-Allow-Origin` back, so the browser will not let that page read the response.

`poc.sh` checks that `nosniff` is present, that `X-Powered-By` is absent, and that the evil origin is not reflected. `poc-samudith.sh` checks that `GET /api/applicantRoles` includes `Strict-Transport-Security` and `Content-Security-Policy`.

## V7 — error details sent to the client

About a hundred `catch` blocks answered with `res.status(500).json({ error: error })`. Express then turned the raw Mongoose error into JSON. Asking for `GET /api/employees/` with an id that is not an ObjectId returned a `CastError` naming the model (`Employee`), the path (`_id`), the rejected value and the kind of cast. That shows an attacker which database library we use and how the collection is keyed (CWE-209). The global error handler also copied `err.message` into the response for every status. The old 404 handler did `console.log(req)`, which wrote the whole request, including the `Authorization` bearer token, into the server log (CWE-532).

`middleware/safe-errors.js` wraps `res.json` once per request. When the body is a plain object and `error` or `err` holds another object, the real error is printed on the server and the client gets a short string. `CastError` becomes `"Invalid identifier"`, `ValidationError` becomes `"Invalid input"`, `MongoServerError` becomes `"Request could not be completed"`, and any other error object becomes `"Something went wrong"`. If the status was already 500 or higher and the error was a `CastError`, the status is lowered to 400.

The employee `show` action catches a bad id itself and sends status 404 with the error object. The wrapper then replaces that object, and because 404 is below 500 it leaves the status alone. So `GET /api/employees/abc` with a manager token comes back as 404 and `{"error":"Invalid identifier"}`. The body has no `CastError`, no `ObjectId` and no `stack`.

The global handler logs the method, the URL and the error, and returns `"Internal server error"` for 5xx. The 404 handler no longer logs the request. `express.json` is limited to 1 MB so a huge body cannot be used to fill memory.

`fbf36c0` changed the log call to a fixed format string, `"[%s %s]"`, and passes the method and URL as later arguments. Node treats the first argument of `console.error` as a format string, so a path containing `%s` or `%o` could have changed what was written. Morgan is also told to log the path only: `logger.token("url", ...)` drops the query string. The Google callback puts the authorization code and the `state` value in that query string, and those must not land in the access log.

`poc.sh` checks that an invalid id response does not contain `CastError` or `ObjectId`. `poc-samudith.sh` also checks the 404 status, the exact message, and that `stack` is absent.
